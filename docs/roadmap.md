- 資源詳情：監控與觀測事件併入總覽與時間軸，機器與路由器分頁精簡為 7 個；歷史資料可依時間範圍查詢。
- 結構與保留期限：機器與路由器共用持久化操作；觀測資料上限改為每個資源各自計算；文件版本、已結束操作與失敗登入紀錄有保留上限，並分批清除；資源列表在 store 篩選與分頁；API 不再依型別列舉（快照改為 `{type, data}`）；資源變更改用非同步訂閱；engine 不在全域鎖內寫入資料庫（schema 16，需手動升級）。

決策紀錄：

- **不做文件指令的完整權限隔離**：`lcm` 帳號的 sudo 範圍都是固定操作，沒有任意 root。另建執行帳號並重做自我部署，代價高、收益小。改為在[架構文件](architecture.md#security-model)寫明能寫文件者可觸及的範圍。
- **connections 的 `allowResources` 是 allowlist**：空清單代表全部拒絕；connections 檔案與上層目錄必須屬於 root；secret 檔案必須是 0600 的一般檔案。
- **控制台維持不用圖表套件**：自製共用 SVG 元件。
- **伺服器訊息改回傳代碼**：由控制台翻譯。
- **機器與路由器的電源確認流程簡化**：一個對話框，自動進入維護，CLI 只需單一確認旗標；伺服器的自動前置檢查保留。
- **稽核紀錄永久保留**：只有失敗登入設數量上限；其他會無限成長的表（版本、已結束操作）依可設定的上限清除，使用中與未結案的資料不刪。
- **中斷的持久化操作**：確定沒有送出才判為失敗，可能已送達裝置或 helper 的一律判為結果不明。

留下的技術債（不影響行為，視需要處理）：資源詳情 DTO 仍依型別帶 `machine`／`router`／`service` 欄位；資源列表的服務仍逐筆讀取部署版本，總覽仍逐筆讀取狀態；機器與路由器的動作可用性仍直接查詢 Git 擁有權。

## 近程：安全自動化與可重現決策

### 進階護欄、核准與受控復原

在既有時段限制之外，補齊可持久化的 cooldown、動作預算、穩定性判斷與 circuit breaker。實體機器維護的必要閘門已交付；完整的通用核准中心獨立交付。

提供核准節點、API 與控制台流程，涵蓋核准、拒絕、逾時、重啟恢復與操作者稽核。核准綁定實際審閱的請求，執行前重新檢查前置條件，不得繞過鎖、護欄或操作來源限制。

完成「穩定異常 → 限次重啟軟體 → 新健康結果驗證 → 超限停止並通知」及觀察／決策／執行／驗證的閉迴路範例。這些範例不授權自動重開整台機器。驗收需包含假時鐘的邊界測試、核准續跑與過期，以及失敗時停止動作的端對端情境。

### 決策重播與 Policy 測試

保存觸發資料、必要讀取結果、時間輸入、狀態快照、判斷、護欄結果與操作請求。以錄下的輸入重跑指定 policy 版本，以模擬或錄製結果取代寫入，再比較新舊決策差異。

提供 lcm replay、*.test.yaml 情境、可納入 CI 的 lcm test，以及控制台重播結果。以即時狀態預覽 policy 與歷史重播分開定義；現有 action dry-run 與 engine 中斷恢復不等同重播或模擬。

待操作副作用與紀錄契約穩定後交付。驗收需證明固定輸入可重現決策、缺失資料有明確結果，且測試／重播不能送出真實寫入。

## 後續：更多控制對象與資源協作

### SSH 遠端 Linux 實體機器

移出當期實作；待本機監控、操作與維護契約穩定後再納管其他既有 Linux 實體機器。不是只增加 Host 設定就視為可用。

- 直接 SSH 使用 pinned host key、明確帳號／identity／timeout 與最小權限，不接受任意 ProxyCommand、forwarding 或未知 host key；secret 不出現在文件／日誌。
- SSH host key 驗證通道，設備身分識別目標，boot ID 識別一次開機；處理同機 alias、cloned identity、位址／host key 改變、OS 重裝與設備替換，不自動接續危險操作。
- 推薦固定受限 helper 與有 schema 的 structured stdin；OpenSSH 遠端命令不等同本機 argv 隔離，不提供任意 root shell。連線可達、OS 觀測與 power 權限分開，無 helper 不假稱已觀測 OS。
- 沿用 durable operation／收據／去重／未知結果／維護語意；SSH 斷線不等於 off，只有 SSH 不能 power-on。整機 power 仍限直接管理員手動。
- 辨識控制端本機與 gateway／storage 等必要控制依賴，避免遠端通道繞過同機安全保護；未處理的危險依賴操作預設拒絕。
- 未納管工作負載標示 partial，明確保存人工維護準備。遠端 Machine 不自動成為 Service 可部署 Host；軟體執行位置另行設計。
- 使用不同設備身分的測試目標驗收 host key／權限、helper 版本、斷線／未知接受狀態、reconnect 非 reboot、去重與控制端復原；不能只用本機 SSH 冒充不同設備。

### 深入機器監控與外部觀測

本機首版只提供有限狀態／事件與短期歷史。後續依需求評估：

- lm-sensors 溫度／風扇與 smartmontools 磁碟健康 collector：先驗證硬體／driver／權限，不自動探測、改 driver、自測或喚醒休眠磁碟。
- Netdata 儀表板連結／connector，或 node_exporter＋Prometheus 的長期指標整合；依現有環境選用，不重建監控平台。現有 Prometheus check 查詢 API 與 exporter /metrics 分開。
- 完整日誌搜尋、較長保留、高頻指標與集中式 journal 由專門工具承擔；新增 LCM 整合時另定來源驗證、去敏感、容量與告警可靠性契約。
- 獨立外部監控端偵測 LCM／工作站離線；同機程序無法在自身關機時即時告警。可靠通知／重播與持久訂閱需另案設計，不把現有 SSE 當成可靠佇列。

統一模型與關係已交付（見上方已完成項目）。其餘依實際需求評估：

### 雲端 VM、遠端軟體與其他資源

- **雲端 VM**：依實際需求選供應商，先納管既有 VM。確認帳號／region scope、穩定身分、非同步任務、權限與完成證據；建立／刪除、配額、費用與 snapshot restore 另定範圍。
- **遠端軟體服務**：在機器 SSH 通道穩定後，明確定義 status、checks、source checkout、build、install、backup 與 jobs 的執行位置；不支援的遠端能力拒絕執行，不能靜默改在本機執行。
- **獨立電源通道**：BMC/Redfish 或獨立 Wake-on-LAN 發送端須有硬體、網路、權限與真實 off/on 證據。喚醒封包送出不等於已開機；不得假定目前工作站具備這些條件。
- **資料庫**：需要專屬維護與資料復原語意時再增加類型；釐清實例／邏輯資料庫、備份一致性、restore 目標與防覆寫。
- **儲存與備份目標**：區分 volume、NAS、snapshot 與備份，定義一致性、保留清理及安全刪除。
- **網路設備**：小米路由器的觀測與受控重開已交付；其他廠牌、設定備份／推送／驗證與復原管道仍待評估，變更須避免切斷控制端（以 `controlPath` 關係標示）。
- **憑證**：串接既有 CA/provider，提供到期、renew、發佈與 reload 驗證，不另建 CA。
- **排程作業與資源群組**：先判斷 policy、run-job、標籤是否已足夠；確實需要獨立身分與生命週期時才新增。

Linux 非 systemd 的控制、其他作業系統、sleep／hibernate、RTC、OS 安裝／更新、provisioning、強制電源操作、RBAC 與 HA 都需獨立需求與驗收。多使用者授權、controller ownership、fencing、資料儲存及故障模型不能由現有單程序架構默認保證。

## 後續：維運決策與設定協作

### SLO 與錯誤預算

支援可用率與延遲目標、滾動時間窗的錯誤預算、控制台呈現及 policy 條件，例如預算不足時暫停部署。先定義缺失／過期資料與維護期間的計算語意。

沿用現有 checks 與外部指標來源，不擴充成完整指標資料庫或儀表板平台。驗收涵蓋時間窗計算與資料不足時的 policy 行為。

### 從控制台送出 Git PR

將 Git 管理文件的控制台修改送成 PR，保留 ownership、drift、衝突處理與樂觀鎖。使用獨立 checkout 與新 branch，不直接寫入來源 branch，也不碰操作者的工作目錄。

文件與 ownership 契約穩定後可獨立於 SLO／重播開發。驗證並行 Git 修改、過期版本、權限不足、secret 遮蔽及 PR 建立失敗不遺失編輯。功能交付前仍以 export 回到 Git。

## 選用：MCP 與 AI 管理

預設關閉，不能成為一般機器管理或確定性 policy 執行的依賴。

### 受管制的 MCP 工具

先提供查詢機器／資源、時間軸、決策與 run 的結構化、去敏感工具，補齊唯讀權限與每個 actor 的活動紀錄。未來寫入工具必須走相同 operation、核准、護欄與稽核路徑，不能成為另一條控制通道。

驗收包含越權拒絕、secret 排除、操作者歸屬及操作限制。MCP client 不可取得 secret、變更權限或修改稽核紀錄。

### 受監督的 AI 執行器

模型執行維持獨立、可替換的 worker，支援遠端或本機 provider。初期採監督模式，能完全關閉並限制每輪／每日用量；AI 失敗或額度耗盡不影響一般 policy。

對話先以控制台為主，訊息整合依需求增加。AI 不可修改自己的權限、護欄、預算或稽核，不可執行不可逆動作；整機電源的手動限制仍有效，除非另案重新設計。

### 調查、彙報與提案

提供附依據的事故調查、每日摘要、操作與 policy 提案。新 policy 先 validate／test；有重播能力後，附上可設定歷史範圍的決策比較再送審。ai.analyze 若納入 policy，其輸出需符合 schema 與允許選項，仍經一般護欄。

遙測文字視為不可信輸入。讀過原始日誌／告警的工作階段，其寫入必須人工核准；只需結構化資料的情境不傳入多餘原文。保存去敏感的模型輸入／輸出供重播使用；新模型／prompt 的實際比較另行執行並計算用量。

可寫入的 AI 提案依賴核准、可靠 operation、權限與稽核；附重播證據的 policy 提案再依賴決策紀錄與模擬。跨系統代表與 A2A 屬研究候選，待有明確互通需求再評估。

## 待釐清需求與發佈要求

以下是待查核的歷史需求，不是已確認缺陷，也不自動成為本次實體機器實作的前置條件：

- Module 刪除，以及修改 Module 對已部署 dependent policy 的版本與重新部署語意。
- Policy 停用、undeploy、刪除或離線期間改動後的 trigger state 清理。
- Trigger Git runner 與其他指令執行路徑的權限／執行邊界。
- Policy 層級 failure handler、target／label selection 的原定需求與現有行為差異。
- 選用的 Prometheus metrics 暴露，與目前 Prometheus health check 分開評估。

確認缺口後建立具驗收條件的 task，已滿足者結案。版本發佈時維護 CHANGELOG，並更新各自負責行為的正式文件，不重新開啟已完成的舊驗收。
